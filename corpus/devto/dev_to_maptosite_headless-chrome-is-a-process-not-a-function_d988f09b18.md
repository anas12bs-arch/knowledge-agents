# Headless Chrome is a process, not a function: lifecycle, memory and failure modes in browser automation

> Source: devto | Category: news | 2026-11-15T16:41:49Z

Thirty-seven orphaned browsers and a full /tmp taught me that headless Chrome is a process tree, not a function call: launch and context and page costs, teardown that survives a SIGKILL, why networkidle never fires, readiness as a DOM predicate, locators vs element handles after a re-render, frames and shadow roots, dialogs and downloads, traces for postmortems, and the retries that duplicate a submit.
